[ ] 4. LIGAR CADA CORRETOR AO LOGIN (auth_user_id)
    SEM ISSO, TODA VISITA CAI EM PENDÊNCIA em vez de virar envio automático:
    a ficha é documento jurídico e a API exige um corretor identificado
    (nome + CRECI) para assinar. O CRM descobre quem é pelo auth_user_id.

    Ver a situação atual:
      select c.id, c.nome, c.auth_user_id, u.email
      from whatsapp.corretores c
      left join auth.users u on u.id = c.auth_user_id
      order by c.nome;

    Ligar por e-mail (repetir para cada corretor):
      update whatsapp.corretores c
      set auth_user_id = u.id
      from auth.users u
      where lower(u.email) = lower('rodrigo@morabilidade.com')
        and lower(c.nome) = 'rodrigo';

    Conferir que o usuário correspondente tem CRECI na API principal:
      select id, nome_completo, creci, ativo, ocultar_creci_ficha
      from usuarios where id = '<auth_user_id>';
    Sem creci (e sem ocultar_creci_ficha = true), a API recusa a ficha — a
    pendência vai chegar dizendo exatamente isso.

COMO O ENVIO DECIDE (para ler a resposta do cron)
--------------------------------------------------
Para cada visita que começa nos próximos 90 minutos, nesta ordem:
  1. texto livre pro CLIENTE      -> só entrega se ele falou com a gente nas
                                     últimas 24h (regra da Meta, não nossa)
  2. template pro CLIENTE          -> a qualquer hora, se o passo 5 estiver feito
  3. pendência pro PLANTÃO         -> mensagem pronta + link, para encaminhar
Cada visita é avisada UMA vez só. Como o gatilho é horário e a janela é de 90
minutos, o aviso sai entre ~30 e ~90 minutos antes da visita.
Quando a ficha não pôde ser gerada, a pendência vem com o motivo exato da API
(ex.: corretor sem CRECI) — é para a ação ser óbvia sem precisar investigar.
